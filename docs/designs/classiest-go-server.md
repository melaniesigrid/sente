## Review findings (compressed; each resolved to the recommended fix)
1. Architecture: kernel = pure modules (board, rules, record, score, sgf, clock) consumed by views. UI never owns rules; Game becomes a thin adapter over GameRecord. Record is JSON-serialisable and replayable, which is the future socket protocol.
2. Errors: tryPlay returning null loses the reason. CRITICAL GAP. Return a reason (occupied, ko, superko, suicide) so the UI can say why. SGF parse throws a named SgfParseError with offset; UI toasts and keeps state. Clock expiry is a named event, not a setTimeout side effect.
3. Security: no backend yet. SGF import is untrusted text: cap at 256 KB, no eval, escape on render. Name field max 24 chars.
4. Edge cases: double-click during bot think (guarded); navigate away mid-game (persist record every move, resume card); zero-move SGF; full board; disputed dead stones after pass-pass; clock hits zero while opponent thinking; undo after end.
5. Code quality: remove the global N; compute star points per size; LESSONS and PROBLEMS carry an explicit size.
6. Tests: superko cycle, 13x13 and 19x19 capture and scoring, GameRecord transitions (illegal ones throw), SGF round-trip on real games, byo-yomi period consumption, dead-stone scoring against known positions. Target: 80 or more engine tests.
7. Performance: 19x19 aiChooseMove runs 361 tryPlays with chain floods; under 10 ms. Superko uses Zobrist hashes stored in a Set on the record.
8. Observability: local-only telemetry ring buffer (last 50 games: size, result, bot, move count). Dev overlay shows record hash and last illegal-move reason.
9. Deploy: GitHub Pages via Actions; rollback is git revert; no users yet so no flags needed.
10. Trajectory: views import through engine/index.js only, never internals.
11. Design: game-end and onboarding are new UI. Hierarchy: board first, status second, controls third. No new chrome; overlays fade. Run a design review before the dark palette.
